## 📌 프로젝트 개요 | Overview

**SemiGuard AI**는 반도체 제조 현장의 장비 센서 데이터를 실시간으로 분석하여 고장 전 이상을 자동 탐지하고, LLM이 원인을 즉시 진단하여 비계획 정지 손실을 예방하는 **예지보전(Predictive Maintenance) 웹 시스템**입니다.

반도체 공장에서 장비 1대가 비계획 정지(Unplanned Downtime)되면 수억 원의 손실이 발생합니다. 기존의 사후 대응 방식에서 벗어나, **AI가 고장 전에 미리 감지하고 원인까지 설명**하는 것이 이 프로젝트의 핵심입니다.

## 🤖 AI 이상탐지 엔진 | AI Anomaly Detection Engine

Isolation Forest 알고리즘의 핵심 원리를 기반으로 구현된 이상탐지 엔진입니다.

**알고리즘 원리**: 각 센서의 z-score를 계산하여 정상 기준값에서 벗어난 정도를 이상 점수(0~100)로 환산합니다. 정상 데이터는 고립시키기 어렵고, 이상 데이터는 쉽게 고립됩니다.

**위험도 4단계**:

| 단계 | 이상 점수 | 색상 | 조치 |
|------|----------|------|------|
| 정상 (Normal) | 0 ~ 29 | 🟢 초록 | 정상 운전 |
| 주의 (Caution) | 30 ~ 49 | 🟡 노랑 | 모니터링 강화 |
| 경고 (Warning) | 50 ~ 69 | 🟠 주황 | 점검 준비 |
| 위험 (Danger) | 70 ~ 100 | 🔴 빨강 | 릴레이 차단 |

**정상 기준값**:

| 센서 | 정상 평균 | 표준편차 |
|------|---------|---------|
| 전류 | 5.0 A | ±0.5 |
| 온도 | 45.0 °C | ±3.0 |
| 진동 | 2.0 mm/s | ±0.3 |
| 소음 | 55.0 dB | ±4.0 |

## 🧠 LLM 이상 원인 분석 | LLM Anomaly Diagnosis

위험/경고 단계 탐지 시 LLM이 센서 데이터를 분석하여 **주요 원인 → 상세 분석 → 권장 조치** 3단계로 자연어 설명을 생성합니다.

- **3개 언어 동시 생성**: 탐지 즉시 한국어·영어·일본어 분석 결과를 병렬로 LLM 호출하여 DB에 저장
- **이상 이력 연동**: 각 이상 로그에 LLM 분석 결과가 함께 저장되어 과거 탐지 건 조회 가능
- **AI 분석 히스토리 패널**: 최근 5건의 LLM 분석 결과를 시간순으로 조회
- **언어 전환 즉시 반영**: 언어 설정 변경 시 저장된 분석 결과도 해당 언어로 즉시 표시

### 적응형 피드백 학습·근거 검증·매뉴얼 RAG

챗봇의 좋아요·싫어요 평가와 부족 사유는 메시지별로 DB에 저장됩니다. `정확하지 않음`, `설명 및 근거 부족`, `질문과 관련 없음`, `기타` 사유에 따라 다음 재생성 답변의 지침을 달리 적용합니다. 이는 모델 가중치를 직접 변경하는 재학습이 아니라, 사용자의 최신 피드백을 안전하게 요약하여 다음 추론의 컨텍스트에 반영하는 **적응형 프롬프트 학습**입니다.

| 구성 요소 | 동작 방식 |
|---|---|
| 피드백 영구 저장 | 메시지별 평가, 사유 코드, 직접 작성 의견을 `chat_feedback`에 저장하고 사용자 계정 단위로 격리합니다. |
| 사유별 재생성 | 정확성 문제는 센서 편차 재계산, 설명 부족은 근거·점검 순서 확장, 관련성 문제는 최신 질문 의도 재확인을 우선합니다. |
| 근거·신뢰도 검증 게이트 | LLM 시스템 프롬프트에 실측값·정상 기준·편차·신뢰도·추가 확인 항목을 강제하고, 서버가 별도 검증 게이트를 답변 하단에 추가합니다. |
| 설비 매뉴얼 RAG | 챗봇의 `매뉴얼` 버튼에서 점검표·매뉴얼 텍스트를 등록하면 문단 단위로 분할하여 저장하고, 질문 키워드와 일치하는 구간을 LLM 컨텍스트에 제공해 출처로 표시합니다. |
| 매뉴얼 출처 클릭 확인 | 답변 하단에 `[번호] 문서명 · 구간` 형태의 출처 배지를 표시하고, 배지를 클릭하면 인용된 매뉴얼 원문을 모달에서 바로 확인하거나 복사할 수 있습니다. |
| RAG 매뉴얼 관리 | 등록된 매뉴얼의 제목·갱신일·청크 수를 확인할 수 있으며, 본인이 등록한 매뉴얼은 연결된 모든 RAG 청크와 함께 확인 절차를 거쳐 삭제할 수 있습니다. |
| RAG 매뉴얼 탐색 | 매뉴얼 관리 화면에서 제목으로 등록된 문서를 빠르게 검색하고, 현재 검색 결과 수와 검색 결과 없음 상태를 한국어·영어·일본어로 확인할 수 있습니다. |
| RAG 매뉴얼 정렬 | 매뉴얼 목록과 제목·원문 검색 결과를 최신순·오래된순·제목순으로 정렬할 수 있어 등록 시점과 설비명을 기준으로 빠르게 탐색할 수 있습니다. |
| RAG 매뉴얼 필터 초기화 | 검색어 또는 정렬이 적용되면 `초기화` 제어가 표시됩니다. 한 번의 동작으로 매뉴얼 검색과 정렬을 기본값으로 되돌릴 수 있습니다. |
| RAG 매뉴얼 정렬 선호도 | 선택한 매뉴얼 정렬 방식은 브라우저에 저장되어 매뉴얼 관리 모달을 다시 열어도 유지됩니다. |
| RAG 청크 안전 안내 | 매뉴얼 등록 전 실제 저장 규칙과 같은 방식으로 예상 청크 수를 계산합니다. 20개 이상이면 장·설비 단위 분할을 안내하고, 서버는 한 매뉴얼당 최대 50개 청크로 제한해 과도한 검색 범위 생성을 방지합니다. |
| RAG 조회 복구 | 매뉴얼 목록·제목/원문 통합 검색·원문 미리보기는 조회 실패를 빈 상태와 구분해 안내하며, 각 영역에서 다른 조회를 방해하지 않고 다시 시도할 수 있습니다. |
| RAG 매뉴얼 통합 검색 | 매뉴얼 관리 검색은 문서 제목뿐 아니라 저장된 원문 청크까지 검색하며, 원문 일치 결과에는 짧은 발췌문을 표시해 검색 이유를 확인할 수 있습니다. |
| RAG 매뉴얼 디바운스 검색 | 매뉴얼 제목·원문 검색은 입력 후 250ms 대기한 뒤 서버에 요청하며, 입력 대기와 검색 진행 상태를 별도로 표시해 불필요한 호출을 줄입니다. |
| 브라우저 호환성 데이터 | 자동 유지보수에서 `baseline-browser-mapping` 데이터를 최신화하여 개발·빌드 시 브라우저 호환성 데이터 최신화 경고를 해소했습니다. |
| RAG 원문 미리보기 | 매뉴얼 관리 목록에서 각 문서의 `원문` 버튼을 누르면, 현재 사용자 소유 문서의 저장된 청크를 순서대로 확인할 수 있습니다. |
| RAG 원문 활용 | 미리보기 중인 매뉴얼 원문은 한 번에 복사하거나, 구간 번호·내보낸 시각·갱신일이 포함된 Markdown 파일로 내려받을 수 있습니다. |
| RAG 출처 관련도 | AI 답변의 매뉴얼 출처는 질문 키워드와 일치한 비율을 함께 표시하며, 원문 모달에서 일치 키워드를 확인해 근거 적합성을 판단할 수 있습니다. |
| 피드백·재생성 히스토리 | 챗봇 헤더의 `피드백` 버튼에서 과거 평가·사유와 그에 따라 재생성된 답변을 최신순으로 모아 볼 수 있습니다(`chat_feedback.regenerated_content`). |
| 피드백 이력 관리 | 히스토리에서 전체·긍정·부정 평가를 분리해 볼 수 있으며, 각 항목 또는 사용자 자신의 전체 피드백 이력을 확인 후 삭제할 수 있습니다. |
| 피드백 사유별 분석 | 부정 평가를 정확성·설명 부족·관련 없음·기타 사유로 세분화해 검색, 기간, 정렬, 페이지네이션과 함께 분석할 수 있습니다. 현재 사유 필터 결과는 CSV 파일명에도 반영됩니다. |
| 피드백 사유별 건수 | 사유별 필터에는 현재 검색어와 기간 조건에 맞는 전체 부정 평가와 정확성·설명 부족·관련 없음·기타 사유의 건수를 함께 표시해, 현재 분석 범위에서 개선 우선순위를 빠르게 파악할 수 있습니다. |
| 피드백 필터 초기화 | 평가 유형·사유·검색어·기간·정렬 중 하나라도 적용되면 `필터 초기화` 제어가 표시됩니다. 한 번의 동작으로 모든 조건을 기본값으로 되돌리고 첫 페이지에서 다시 확인할 수 있습니다. |
| 피드백 정렬 선호도 | 선택한 피드백 이력 정렬 방식은 브라우저에 저장되어 피드백 패널을 다시 열어도 유지됩니다. |
| 피드백 사유 필터 선호도 | 선택한 부정 평가 사유 필터는 브라우저에 저장되어 피드백 패널을 다시 열어도 유지됩니다. |
| 피드백 평가 유형 선호도 | 전체·긍정·부정 평가 유형 필터 선택은 브라우저에 저장되어 피드백 패널을 다시 열어도 유지됩니다. |
| 피드백 검색어 선호도 | 입력한 피드백 검색어는 브라우저에 저장되어 피드백 패널을 다시 열어도 분석 맥락을 유지합니다. |
| 피드백 빠른 기간 선택 | 피드백 이력에서 전체·오늘·최근 7일·최근 30일을 빠르게 선택할 수 있으며, 직접 날짜를 고르면 사용자 지정 기간으로 전환됩니다. |
| 피드백 기간 선호도 | 선택한 빠른 기간은 브라우저에 저장되며, 패널을 다시 열면 오늘·최근 7일·최근 30일 설정이 최신 날짜 기준으로 다시 적용됩니다. |
| 피드백 상담 맥락 보기 | 각 피드백 카드의 `상담 맥락 보기`에서 평가한 답변이 포함된 대화 흐름을 확인할 수 있습니다. 서버의 사용자 소유 세션 검증을 그대로 사용하며, 평가한 답변은 상세 패널에서 강조 표시됩니다. |
| 피드백 조회 복구 | 피드백 이력 또는 상담 맥락을 불러오지 못하면 빈 목록처럼 표시하지 않고 실패 원인을 구분해 안내하며, 해당 영역에서만 다시 시도할 수 있습니다. |
| 피드백 분석·보호·내보내기 | 긍정·부정 평가 수와 비율을 요약바로 확인하고, 현재 필터 결과를 Excel 호환 UTF-8 BOM CSV로 내려받을 수 있습니다. 전체 삭제는 두 단계의 확인을 거쳐야 실행됩니다. |
| 피드백 탐색 경험 | 긍정·부정 비율은 녹색·적색 애니메이션 바로 시각화되며, 답변·사유·재생성 내용 검색과 5건 단위 페이지네이션으로 많은 이력을 빠르게 탐색할 수 있습니다. |
| 피드백 심화 분석 | 시작일·종료일 범위와 최신순·과거순 정렬을 조합해 이력을 살펴볼 수 있으며, 현재 필터 결과의 반복 핵심어·요약·개선 방향을 AI가 구조화해 제시합니다. |

### 안전 중심 유지보수

프로젝트에는 8시간 간격의 안전 점검 작업이 설정되어 있습니다. 이 작업은 TypeScript·Vitest 회귀 테스트, 오류 로그, 접근성, 모바일 반응형, 다국어 표현을 우선 확인합니다. 검증 가능한 작은 수정만 기록·반영하며, 데이터 삭제, 인증 정보 변경, 결제, 외부 게시, 대규모 구조 변경은 자동으로 실행하지 않습니다.

최근 개발 로그 점검에서는 브라우저 콘솔 오류와 최근 네트워크 4xx·5xx 응답이 확인되지 않았습니다. 과거 개발 중의 JSX 파싱·테스트 실패 기록은 이후 빌드 및 전체 회귀 테스트 통과로 해소된 상태이며, LLM 사용량 소진 응답은 기존의 다국어 센서 근거 기반 안전 대체 진단 흐름으로 처리됩니다.

모바일 미리보기에서 일시적으로 보인 초기 로딩 화면도 다시 점검했습니다. 최근 비정상 HTTP 응답은 없었고, 콘솔의 전송 오류·HMR 실패 기록은 이전 개발 시각에만 남아 있으며 이후 TypeScript·전체 회귀 테스트·프로덕션 빌드가 통과했습니다. 따라서 현재 상태에서는 지연 로딩 초기 화면이 캡처된 것으로 분류합니다.

대시보드 모듈 로딩이 8초를 넘길 경우에는 로딩이 길어지고 있음을 다국어로 알리고, 사용자가 원할 때만 페이지를 새로고침할 수 있는 복구 제어를 표시합니다. 정상적인 빠른 로딩에서는 이 제어가 나타나지 않습니다.

프로덕션 의존성 감사에서는 직접·전이 패키지의 업데이트 또는 검토 권고를 별도로 기록합니다. 인증, RAG 문서 처리, HTML 정제 흐름에 영향을 줄 수 있는 의존성은 호환성·회귀 영향이 확인되기 전에는 자동 업그레이드하지 않으며, 별도의 검증 작업으로만 처리합니다.

> **안전 원칙**: 위험 단계 판정과 장비 제어는 규칙·임계값 엔진이 담당합니다. LLM은 근거 기반 분석, 추가 확인 요청, 점검 순서 제안만 수행하며 임계값을 임의로 변경하거나 장비를 직접 제어하지 않습니다.

## ✨ 주요 기능 | Key Features

- **실시간 센서 대시보드**: 전류·온도·진동·소음 4종 센서값을 라인 차트로 실시간 시각화
- **AI 위험도 게이지**: 이상 점수 0~100을 원형 게이지와 4단계 색상으로 직관적 표현
- **LLM 이상 원인 분석**: 위험 탐지 시 AI가 원인·상세·권장 조치를 자연어로 즉시 진단
- **예상 절감 비용 자동 산출**: 위험 단계 탐지 1회당 약 5천만 원 절감 효과 누적 표시
- **장비 상태 시뮬레이터**: 정상/이상/주의/경고 주입 버튼으로 AI 반응 직접 체험
- **자동 데모 모드**: 설정 속도로 자동 데이터 주입 및 AI 분석 시연
- **이상 이력 로그**: 탐지된 이상 이벤트와 LLM 분석 결과를 DB에 저장하고 테이블로 조회
- **AI 분석 히스토리 패널**: 최근 LLM 분석 결과 5건 모아보기
- **임계값 커스터마이징**: 위험도 4단계 및 센서별 임계값을 UI에서 직접 조정
- **PDF 리포트 내보내기**: 현재 대시보드 상태를 PDF로 저장
- **CSV 이상 이력 내보내기**: 이상 로그를 CSV 파일로 다운로드
- **한국어 / 영어 / 일본어 다국어 지원**: 우측 상단 버튼으로 즉시 전환

git clone https://github.com/1213ghgo-kimdy1217/semiguard-ai.git

# 2. 의존성 설치
pnpm install

# 3. 환경변수 설정 (.env)

pnpm dev
