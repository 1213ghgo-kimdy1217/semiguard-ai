## 프로젝트 개요

SemiGuard AI는 전류·온도·진동·소음 데이터에서 위험 신호를 찾고, 현장 담당자가 **무엇이 변했는지**, **왜 점검해야 하는지**, **무엇부터 확인할지**를 한 화면에서 이해하도록 돕는 웹 기반 예지안전 시스템입니다. 위험 점수만 표시하는 대신 센서 근거, 이상 이력, AI 보조 설명, 권장 점검 순서를 연결해 판단 과정을 투명하게 만드는 것이 목표입니다. 궁극적으로는 실제 팹의 승인된 읽기 전용 데이터를 바탕으로 엔지니어의 점검 판단을 더 빠르고 일관되게 돕되, 현장 안전 판단과 설비 제어 책임은 담당자와 기존 절차에 남기는 단계적 보조 시스템을 지향합니다.

이 프로젝트는 실제 설비를 자동 제어하지 않습니다. 화면의 데이터와 위험 시나리오는 교육·시연 또는 연동 데이터 확인을 위한 것이며, 실제 안전 조치와 운전 판단은 담당자가 현장 절차에 따라 수행해야 합니다.

| 프로젝트 확인 항목 | SemiGuard AI의 대응 |
|---|---|
| 해결하려는 문제 | 여러 센서 수치를 해석하고 점검 우선순위를 정하는 데 시간이 걸리는 문제 |
| 핵심 경험 | 위험 신호 → 센서 근거 → AI 보조 설명 → 권장 점검 순서 |
| 즉시 체험 | 로그인 없는 [읽기 전용 30초 데모](https://semiguardai-jifnzsvd.manus.space/demo) |
| 신뢰성 장치 | 이상 이력, 다국어, 근거 표시, AI 불가 시 규칙 기반 대체, 모바일 접근성 |

## 1주차 팀 목표

> **우리는 반도체 장비 유지보수 담당자가 여러 센서에서 위험 신호가 나타났을 때 겪는 점검 우선순위 판단의 어려움을, 센서 근거와 AI 보조 설명·권장 점검 순서를 연결하는 읽기 전용 예지안전 대시보드로 줄인다.**

8주 동안의 북극성 지표는 **주 1회 이상 위험 신호부터 권장 점검 순서까지 분석 흐름을 끝까지 확인한 사용자 수**입니다. 오늘 기준은 실제 사용자 측정 시작 전 **0명**이며, 코칭 기간의 가설 목표는 교육·시연 참여자 **5명**의 분석 흐름 완료와 최소화된 피드백 확보입니다. 실측값·역할 분담·팀 규칙·주간 리듬은 [W1 팀 목표 1장](W1_TEAM_GOALS.md)에서 관리합니다.

### 서비스 내 가상 팹 데모와 분석 결과 저장

1. 대시보드의 메뉴에서 **가상 팹 위험 시나리오**를 선택합니다.
2. 전류·온도·진동·소음이 함께 상승한 가상 진공 펌프 시나리오와 AI 보조 분석 결과를 확인합니다.
3. 상단 상태 뱃지에서 `가상 · 승인 전 · 읽기 전용`을 확인합니다. 이 모드는 실제 파일럿·보안 승인 전의 시연 데이터이며, 실제 설비·사용자 데이터나 제어 명령을 사용하지 않습니다.
4. AI 분석 결과 패널의 `TXT` 또는 `PDF`를 선택해 점검용 텍스트 파일을 저장하거나, 인쇄 창에서 PDF로 저장합니다. `TXT` 파일명과 인쇄 창 차단 안내는 현재 선택한 한국어·영어·일본어 언어 설정을 따릅니다.
5. 기간별 센서 차트에서 확대해 확인한 구간은 `PNG` 또는 `JPEG`로 저장할 수 있습니다. 저장 파일명과 데이터 없음·브라우저 렌더링·파일 생성 실패 안내도 현재 언어 설정을 따릅니다.

> 가상 팹 시나리오는 심사·교육용 읽기 전용 데이터입니다. 실제 장비 제어, 레시피 변경, PLC 명령 전송 기능은 제공하지 않습니다.

## 탐지 방식과 검증 상태

현재 위험 신호 탐지는 학습된 고장 분류 모델이나 Isolation Forest 라이브러리가 아니라, **고정된 정상 기준에서 센서 값이 얼마나 벗어났는지 계산하는 z-score 기반 규칙형 위험 점수**입니다. 각 센서의 절댓값 z-score에 8을 곱하고 센서별 기여도를 25점으로 제한한 뒤, 4개 센서의 합을 최대 100점으로 제한합니다. 따라서 이 점수는 현재 기준에서의 편차 크기를 일관되게 보여 주는 데 사용되며, 특정 고장 원인이나 현장 정확도를 직접 의미하지 않습니다.

| 항목 | 현재 구현과 상태 |
|---|---|
| 입력 데이터 | 전류·온도·진동·소음의 **시뮬레이션 데이터**와 향후 승인된 읽기 전용 연동 데이터를 위한 형식입니다. 현재 공개 데모와 기본 폴링은 실제 팹 데이터가 아닙니다. |
| 기준값 | 전류 5.0±0.5A, 온도 45±3°C, 진동 2.0±0.3mm/s, 소음 55±4dB를 시연 기준으로 사용합니다. 실제 장비별 기준은 승인된 과거 로그와 담당자 검토 후 별도로 보정해야 합니다. |
| 점수 계산 | `min(round(Σ min(8 × |(x - μ) / σ|, 25)), 100)`으로 계산하며, 위험 단계의 기본 구간은 0~29 정상, 30~49 주의, 50~69 경고, 70~100 위험입니다. 대시보드에서 단계 경계는 설정할 수 있습니다. |
| AI의 역할 | LLM은 계산된 센서 수치·편차·위험 단계를 자연어 점검 설명으로 정리합니다. LLM이 위험 점수를 계산하거나 고장을 확정하지 않습니다. |
| 검증 상태 | 코드 수준의 점수 계산 회귀 테스트는 갖추었지만, 실제 팹 로그로 정확도·오탐·미탐·사전 경고 시간을 측정한 결과는 아직 없습니다. |

> 공개 `/demo`의 **탐지 방식과 검증 상태** 패널은 위의 계산 구조, 시뮬레이션 경계와 실증 전 한계를 한국어·영어·일본어로 동일하게 안내합니다. 실제 정확도, 비용 절감, 장비 제어 효과를 확정된 성과로 주장하지 않습니다.

실제 도입 전에는 승인된 과거 로그에서 사건 시점과 점수 변화를 비교하고, 오탐·미탐·사전 경고 시간·담당자 해석 가능성을 읽기 전용 범위에서 확인해야 합니다. 데이터 항목, 평가 절차, 지표 정의와 결과 보고 형식은 [실증 검증 계획](VALIDATION_PLAN.md)에 정리했습니다.

## AI 활용과 안전 원칙

AI는 센서 수치와 위험 단계에 근거한 **설명 보조 도구**입니다. AI가 특정 고장을 확정하거나 설비를 제어하지 않으며, 실제 점검·운전 판단은 담당자의 현장 검증과 안전 절차를 따릅니다. AI 서비스가 지연되거나 불가한 경우에는 센서 편차와 위험 단계에 기반한 다국어 규칙 요약으로 전환되며, 대체 분석의 제목·근거·권장 조치는 현재 선택한 한국어·영어·일본어로 표시됩니다.

첫 분석 안내를 마친 사용자는 사용 편의 평점과 가장 어려웠던 단계를 **선택형 항목**으로 남길 수 있습니다. 이 피드백은 사용자별 최신 응답 1건의 평점·단계·시각만 저장하며, 이름·연락처·설비 데이터·자유 입력은 수집하지 않습니다. 관리자 화면은 응답 수, 평균 편의, 단계별 어려움 신호를 선택 기간의 **집계값만** 표시합니다.

AI가 받는 데이터, 매뉴얼 RAG의 경계, 기간 보고서 요약과 위험 전망의 한계는 [AI_USAGE.md](AI_USAGE.md)에서 확인할 수 있습니다. 상세 구현과 복구·접근성 설계는 [TECHNICAL_REFERENCE.md](TECHNICAL_REFERENCE.md)에 정리했습니다.

## 실제 팹 도입 경로

SemiGuard AI는 실제 반도체 팹에서 **읽기 전용 예지안전 보조 시스템**으로 도입하는 것을 목표로 합니다. 현재 버전은 위험 신호, 센서 근거, 이상 이력, AI 보조 설명, 권장 점검 순서를 제공하지만 설비의 가동·정지·레시피 변경 같은 제어 명령은 전송하지 않습니다.

위의 애플리케이션 내부 구조가 실제 팹에 연결될 때는 아래처럼 **승인된 데이터 복제본만 한 방향으로** 전달받는 형태를 전제로 합니다. 각 보안 조치는 향후 현장 파일럿 전 설비·IT/OT 담당자와 확정해야 하는 도입 기준이며, SemiGuard AI에서 설비·PLC로 되돌아가는 제어 경로는 현재 제공하지 않습니다.

```text
[설비 센서 · PLC · MES]
  - 승인된 태그 목록 · 읽기 전용 서비스 계정 · 제어 권한 미부여
          │  승인된 데이터 복제본만 전달
          ▼
[현장 게이트웨이 · Historian]
  - 망 분리 구간 · 최소 권한 · 수집 원본 감사 로그
          │  허용된 목적지 · 암호화 전송 · 전송 기록
          ▼
[SemiGuard AI 데이터 수집 API]
  - 스키마 검증 · 장비별 접근 토큰 · 요청 속도 제한
          │
          ├── [위험 점수 · 이상 이력 · AI 보조 설명]
          │     - 역할 기반 조회 · 변경 이력 · 보존 정책
          └── [대시보드 · 기간 보고서 · 담당자 점검 순서]
                - 인증된 사용자 · 역할별 화면 · 내보내기 권한

※ SemiGuard AI ──X──> 설비 제어 명령 (현재·파일럿 범위 모두 미제공)
```

| 단계 | 도입 범위 | 확인 기준 |
|---|---|---|
| 1. 과거 로그 검증 | 익명화되거나 승인된 과거 센서 로그를 대시보드 형식으로 비교 | 실제 이상 시점과 위험 신호·권장 점검 순서의 일치 여부 |
| 2. 단일 장비 파일럿 | 한 대 장비의 PLC·MES·센서 게이트웨이에서 복제된 읽기 전용 데이터를 조회 | 지연 시간, 오탐·미탐, 담당자의 해석 가능성 |
| 3. 현장 절차 검증 | 장비 담당자와 기존 점검 절차에서 보고서·AI 근거를 함께 검토 | 기존 안전 절차와의 정합성, 개선할 화면·알림 |
| 4. 승인된 범위 확대 | 검증된 데이터 계약과 운영 기준을 다른 장비·라인에 적용 | 데이터 권한, 기록 보존, 장애 대응, 책임 범위 |

팹 도입 전에는 설비·IT/OT 보안 담당자의 데이터 접근 승인, 네트워크 분리 정책, 최소 권한, 현장 안전 절차를 확인해야 합니다. **AI 설명과 위험 전망은 엔지니어의 점검을 돕는 근거이며, 특정 고장을 확정하거나 현장 안전 판단을 대체하지 않습니다.**

### 향후 도입 검토 순서

아래는 대회 이후 실제 팹 도입을 **검토하게 될 경우의 조건부 순서**입니다. 현재 제출 버전은 가상 데이터 기반의 읽기 전용 시연이며, 실제 일정·파일럿 진행·적용 범위는 확정하지 않았습니다. 모든 단계는 협력 기관의 데이터 제공, IT/OT 보안 승인, 현장 담당자 협의가 완료된 경우에만 별도로 논의합니다.

| 검토 순서 | 논의 대상 | 다음 단계 검토 조건 |
|---|---|---|
| 1. 과거 로그 검토 | 승인된 과거 센서 로그의 데이터 형식과 이상 시점 비교 가능성 | 장비 ID, 시간, 전류·온도·진동·소음 값의 최소 데이터 계약 합의 |
| 2. 보안·권한 검토 | 읽기 전용 접근, 망 분리, 최소 권한, 보존 정책 | 협력 기관의 IT/OT 보안 검토와 담당 범위 확인 |
| 3. 단일 장비 파일럿 논의 | 한 대 장비의 승인된 읽기 전용 복제 데이터 활용 가능성 | 오탐·미탐·응답 지연·현장 점검 절차에 대한 담당자 검토 |
| 4. 범위 확대 검토 | 검증 기록을 바탕으로 다른 장비·라인 적용 가능성 | 추가 승인, 변경 이력, 장애 대응 절차, 책임 범위 합의 |

> 발표에서는 “AI가 장비를 직접 멈추는 시스템”이 아니라, “엔지니어가 더 빨리 확인할 수 있도록 위험 근거와 점검 순서를 정리하는 읽기 전용 의사결정 보조 시스템”이라고 설명하는 것이 현재 구현 범위와 일치합니다.

## 다국어 지원

화면·접근성 레이블·날짜 및 시간·AI 대체 안내는 한국어, 영어, 일본어를 지원합니다. 선택형 첫 사용 피드백을 포함한 대화상자는 초기 포커스, Escape 종료, Tab·Shift+Tab 내부 순환을 제공하며, 사용자는 `나중에`를 선택해 해당 브라우저의 자동 재안내만 숨긴 뒤 고정된 수정 제어에서 언제든 응답할 수 있습니다. 이 재안내 선택은 제품 지표로 전송하지 않는 브라우저 선호도입니다. 사용자가 선택한 언어와 테마도 브라우저에 저장되며, 보조기기가 현재 언어를 해석할 수 있도록 문서 언어 속성도 동기화합니다.

### 대시보드 성능 검토

대시보드는 차트·기간 분석·읽기 전용 안전 안내를 한 화면에서 제공하므로 프로덕션 빌드에서 큰 청크 경고가 발생할 수 있습니다. 현재는 Vite의 의존성 그래프와 대시보드 지연 로딩 경계를 유지합니다. Recharts를 수동 `manualChunks`로 분리하는 후보는 기존 번들 계약과 충돌해 적용하지 않았습니다. 이후 성능 개선은 기능별 지연 경계를 별도 검토하고, 인증 지연 복구·차트·보고서·공개 데모 회귀를 함께 확인하는 방식으로만 진행합니다.

### 운영 의존성 보안 상태

2026-08-16 운영 의존성 감사 후 DOMPurify를 **3.4.13**으로 통일하고 직접 Nano ID 의존성을 **5.1.16**으로 올렸습니다. 2026-08-19에 `pnpm audit --prod --json`으로 운영 의존성 감사를 다시 실행했으며, 결과는 critical 0건, high 3건, moderate 16건, low 3건으로 총 22건입니다. high 항목은 Express 4.21.2의 전이 `path-to-regexp@0.1.12`, Streamdown→Mermaid 계열의 `lodash-es@4.17.21`, Recharts의 `lodash@4.17.21` 경로입니다. 현재 서버 경로에는 공식 권고에서 설명한 3개 이상 매개변수 결합 세그먼트 형태가 정적으로 발견되지 않았지만, 설치된 전이 버전 자체는 별도 호환성 검토가 필요합니다.

`path-to-regexp`의 권고 버전 고정이나 Express·Streamdown·Recharts 계열 업데이트는 라우팅·마크다운 렌더링·차트 호환성에 영향을 줄 수 있으므로 자동 적용하지 않습니다. Express 4.21.2는 현재 `path-to-regexp@0.1.12`를 정확한 버전으로 선언하므로 재정의도 설치 계약 변경으로 취급합니다. 각 변경 후보는 별도 호환성 검토, 전체 타입·회귀·빌드, 공개 데모·로그인 흐름 확인을 거친 뒤에만 반영합니다. 세부 분석과 출처는 [의존성 보안 검토](DEPENDENCY_SECURITY_REVIEW.md)에서 확인할 수 있습니다.
