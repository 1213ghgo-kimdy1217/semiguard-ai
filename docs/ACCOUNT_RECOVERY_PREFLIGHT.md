# 계정 복구 스키마 적용 전 점검

이 문서는 메타데이터 점검 도구의 사용법입니다. 도구를 추가한 사실은 운영 DB 연결·변경·배포·메일 발송의 근거가 아닙니다. 기존 [계정 복구 적용 조건](ACCOUNT_RECOVERY.md)과 별도 승인을 따릅니다.

## 실행 범위

`scripts/check-account-recovery-schema.ts`는 운영자가 명시한 `DATABASE_URL`에 연결하여 현재 선택된 DB의 `information_schema.TABLES`, `COLUMNS`, `STATISTICS`만 조회합니다. 회원·답안·비밀번호 해시·토큰 행을 읽지 않고, 스키마명·호스트·사용자·접속 주소·원문 오류를 출력하지 않습니다. 출력은 고정된 상태와 허용 목록의 누락/불일치 항목입니다.

`.env` 및 앱의 DB/설정 모듈을 불러오지 않습니다. 인증정보를 명령행 인수로 주지 마세요. 승인된 연결 관리 방법으로 프로세스에 값을 전달하고 Git·공개 링크·화면 캡처에 남기지 마세요. DB명이 출력되지 않으므로 실행 전 운영자의 비공개 연결 관리 화면에서 대상이 승인된 사용자 소유 DB인지 직접 확인해야 합니다. 이 도구는 대상 소유권을 판정하지 않습니다.

```powershell
node --import tsx scripts/check-account-recovery-schema.ts --help
```

`--help`는 환경 값 확인·DB 연결 없이 사용법만 표시합니다. 운영자가 승인된 프로세스 환경에 값을 준비한 뒤 실행하는 명령은 다음과 같습니다. 이 예시에는 비밀값이 없습니다.

```powershell
node --import tsx scripts/check-account-recovery-schema.ts
```

연결은 인증서와 호스트명 검증을 모두 켭니다. `mysql://` URL의 경로로 DB를 지정하며 query는 없거나 JSON `ssl` 하나만 허용합니다. 해당 JSON은 `rejectUnauthorized: true`, `verifyIdentity: true`, 선택적인 공개 CA(`ca`)만 허용합니다. 다른 query 옵션, 명시적인 검증 해제, 중복 옵션, URL fragment는 거절합니다. 값이 틀리거나 인증이 막혀도 보호를 약화하여 재시도하지 않습니다. `SET TRANSACTION READ ONLY`, TiDB noop 설정, 권한 변경을 실행하지 않습니다.

## 판정과 종료 코드

| 상태 | 종료 코드 | 의미와 다음 단계 |
| --- | --- | --- |
| `ready` | 0 | 필요한 컬럼·테이블·제약이 메타데이터와 일치. 트랜잭션/메일/로그인 성공을 뜻하지 않음 |
| `absent` | 2 | 기존 `users`/`account_revocations`는 있고 새 컬럼과 세 테이블은 모두 없음. 수동 변경 검토 후보이며 자동 적용하지 않음 |
| `partial` | 3 | 일부 존재·타입/기본값/NULL/인덱스 불일치 또는 기존 필수 테이블 누락. 중단하고 정확한 차이를 검토 |
| `unavailable` | 1 | 입력·연결·메타데이터 확인 실패. 원문 오류/접속정보를 출력하지 않고 중단 |

점검 항목은 `users.auth_version`의 부호 있는 INT·NOT NULL·기본값 0, 새 세 테이블의 정확한 컬럼 집합/타입/길이/enum/NULL, 전체 길이 PK·이메일 고유 인덱스·소유자/만료 인덱스입니다. 기존 필수 테이블이 뷰이면 통과하지 않습니다. 새 테이블의 예기치 않은 추가 컬럼도 검토 대상으로 남깁니다. 기존 다른 회원 컬럼/테이블은 변경하거나 열람하지 않습니다.

오직 미적용 상태에서 승인된 [수동 SQL](../drizzle/account_recovery.sql)의 범위를 검토합니다. 이 SQL은 비멱등이며 DDL 도중 일부가 이미 적용될 수 있습니다. `partial`에서 파일 전체 재실행, `db:push`, `CREATE IF NOT EXISTS`로 차이 숨기기를 하지 않습니다. 도구에는 마이그레이션 실행 경로가 없습니다.

## 배포와 후속 검증

이 코드는 활성화 플래그가 0이어도 기존 회원 조회가 새 컬럼을 읽고 탈퇴가 새 테이블을 사용합니다. Production과 연결된 Preview 모두 스키마 검증을 마친 뒤 별도의 배포 승인을 받아야 합니다. 적용 전 배포를 하지 않습니다. 기본값 0과 기존 세션/회원 기록을 보존하며 기존 프로필/소셜 이메일을 인증 완료로 채우지 않습니다.

`ready` 이후에도 별도 승인된 합성 테스트 공간에서 실제 TiDB 동시 재설정 1회 성공, 실패 시 원자적 원복, 고유 이메일 충돌, 지속 제한, 이전 세션 거절을 확인해야 합니다. 그다음 승인된 테스트 계정·수신 주소로 실제 메일 왕복을 확인합니다. 이 도구는 해당 검증이나 기존 사용자의 학습 기록 보존 검증을 대신하지 않습니다.

재설정이 한 번이라도 실행된 뒤에는 세션 버전을 낮추거나 버전을 검사하지 않는 이전 코드로 되돌리지 않습니다. 발송 중단 시에도 세션 버전 검사는 유지합니다. 별도 스키마/환경 변경과 합성 데이터 추가·정리, 메일 서비스/발신 주소/서버 Secret, main 반영·배포는 각각 승인된 범위 안에서만 수행합니다.
