# 체험 화면과 보라색 램프 연결 — v2 예제

현재 보드·보라색 램프·LED 드라이버의 실제 모델은 **미정**입니다. 제공하는 스케치는 클래식 Arduino UNO/Nano 계열을 가정한 PWM 예제이며, 업로드·실물 배선·광량 검증을 완료한 상태가 아닙니다. 보드와 램프가 정해지면 전원·드라이버·고정 구조를 그 부품에 맞춰 확정해야 합니다.

## 조명의 역할

| 위치 | 역할 | 제어 |
| --- | --- | --- |
| 원통형 챔버 안 중앙 보라색 램프 1개 | 플라즈마와 RF 전력 변화를 교육용으로 표현 | 웹 체험의 밝기 값에 따라 PWM 0–255 |
| 원통 바깥, 외함 내부 왼쪽 대각선 위 흰 조명 | 닫힌 문 안에서 카메라 시야 확보 | 별도 정격 전원/디머로 일정하게 점등 |
| 원통 바깥, 외함 내부 오른쪽 대각선 위 흰 조명 | 그림자와 어두운 부분 보완 | 별도 정격 전원/디머로 일정하게 점등 |

이상 주입으로 깜빡이는 것은 보라색 램프뿐입니다. 흰 보조 조명을 같은 PWM 채널에 묶으면 카메라 영상까지 어두워지므로 분리합니다. 화면의 RF·압력·가스·배기 값은 체험용 시뮬레이션 값입니다. 이 예제는 RF 전력이나 실제 광량을 측정하지 않습니다.

## 실제 부품이 정해진 뒤 연결할 순서

1. 보드의 정확한 모델, 보라색 램프의 정격 전압·전류·소비전력, 밝기 조절 방식부터 확인합니다. USB 램프나 자체 컨트롤러가 있는 제품은 전원선을 PWM으로 끊는 방식이 지원되는지 별도 확인합니다.
2. 해당 램프에 맞는 외부 LED 드라이버와 전원을 고릅니다. 드라이버가 보드의 PWM 논리 전압·주파수·극성을 지원하는지 확인합니다. GPIO에 램프나 LED 스트립 전원을 직접 연결하지 않습니다.
3. 예제의 `PURPLE_PWM_PIN = 9`는 **드라이버 제어 입력**용입니다. 클래식 UNO/Nano에서만 가정한 핀이므로 다른 보드는 핀과 해상도를 다시 확인합니다. 공통 GND 또는 절연 입력 연결은 선택한 드라이버 매뉴얼을 따릅니다. 릴레이는 이 빠른 밝기 조절용으로 사용하지 않습니다.
4. 기본은 PWM 활성 High입니다. `PWM_ACTIVE_LOW` 변경은 드라이버 입력 사양과 실제 OFF 레벨을 확인한 뒤에만 합니다. MCU 초기화 이전에도 드라이버가 OFF를 유지하도록 필요한 입력 풀다운/풀업은 드라이버 사양에 맞춰 정합니다. 스케치만으로 전원 투입 순간의 입력 상태를 보장할 수 없습니다. 전원 켤 때와 USB 케이블을 뺄 때 보라색 램프가 꺼지는지 낮은 밝기로 먼저 확인합니다.
5. 흰 보조등 2개와 카메라는 별도로 켭니다. 웹의 **모듈 카메라 → 카메라 설정**에서 모듈에 장착한 외부 웹캠을 확인해 등록한 뒤 연결하고 노출을 맞춥니다. 모듈 웹캠이 없으면 미연결로 유지하며, 내장 카메라로 대체하지 않습니다. USB 직렬 연결이 카메라 영상을 전송하지는 않습니다.

보드 USB 전원과 램프 전원은 각각 정격을 확인합니다. 구매 목록이나 확정 배선도가 필요한 단계에서는 보드·램프·드라이버 모델 세 가지가 필요합니다.

## 브라우저 연결

배포된 HTTPS 페이지 또는 개발용 localhost에서 데스크톱 Chrome/Edge를 사용합니다. `USB 연결`을 직접 누른 뒤 사용자가 포트를 선택합니다. 카메라 권한과 USB 포트 권한은 각각 허용해야 합니다. 미리보기 iframe에서 직렬 권한이 차단되면 사이트를 새 탭으로 엽니다. 브라우저나 조직 정책에서 Web Serial을 막는 경우에는 USB 제어 없이 화면 체험을 사용할 수 있습니다.

포트를 열었다는 이유만으로 연결 완료를 표시하지 않습니다. 기대한 v2 장치 프레임을 받아야 연결 상태가 됩니다. 8초 동안 확인되지 않는 장치나 기존 v1 펌웨어에는 램프 명령을 보내지 않습니다. 기존 v1 데모와 이 v2 체험 펌웨어는 별개입니다. 아무 보드에나 이 예제를 업로드하지 말고 부품 확정 뒤 맞는 프로젝트인지 확인합니다.

## 앱 코드 연결 계약

`useBoothDevice()`는 `status`, `connected`, `supported`, `error`, `lastAckAt`, `acknowledgedBrightness`, `connect()`, `disconnect()`, `sendState({lampBrightness, faultActive})`를 제공합니다. 추가로 마지막 프레임과 수신 시각을 읽을 수 있습니다. `connect()`는 버튼 클릭 안에서 직접 호출합니다.

체험 엔진의 현재 상태를 약 100ms 간격으로 `sendState`에 전달합니다. 밝기는 0–255이며 소수는 반올림합니다. 이 함수의 `true`는 최신 상태가 전송 대상으로 접수됐다는 뜻입니다. 기기가 실제로 처리한 명령은 `lastAckAt`과 `acknowledgedBrightness`로 구분합니다. **ACK도 펌웨어가 적용한 출력 명령의 확인이며, 램프가 실제 그 밝기로 빛났다는 센서 피드백은 아닙니다.**

체험 준비·종료 후 복기 중에도 연결을 유지하며 `lampBrightness: 0, faultActive: false`를 새 상태로 제공합니다. 기록을 읽는 동안 종료 시점의 깜빡임을 반복하지 않습니다. 그래프·수치는 종료 기록으로 고정하며, 연결된 카메라 영상은 실시간일 수 있음을 화면에 구분해 표시합니다.

- 확인된 장치에만 초당 최대 10개를 보냅니다. 느린 직렬 연결에 과거 깜빡임 명령을 쌓지 않고, 최신 상태 하나와 확인 대기 명령 하나만 보관합니다.
- 같은 밝기라도 최신 상태가 계속 제공되면 약 500ms마다 생존 명령을 보냅니다. 앱이 400ms 넘게 새 상태를 주지 않으면 오래된 상태를 재전송하지 않습니다.
- 2초 동안 새 장치 프레임이나 명령 ACK가 오지 않으면 전송을 멈추고 연결을 닫습니다.
- 탭 숨김, 페이지 이동, 연결 해제, 컴포넌트 제거 시 대기 상태를 버리고 추가 쓰기를 멈춥니다. 펌웨어는 마지막 정상 명령 이후 2초가 지나면 보라색 출력을 OFF로 바꿉니다. 탭으로 돌아왔을 때는 다시 연결합니다.
- USB 연결이 없는 상태에서도 시뮬레이션과 카메라 화면을 사용할 수 있습니다. 물리 램프와의 동기화는 USB 장치를 확인한 뒤에만 가능합니다.

## v2 직렬 규약

115200 baud, UTF-8/ASCII, 줄 끝 LF입니다. 브라우저 → 장치 명령은 다음 한 줄뿐입니다.

```text
EXPERIENCE 42 180 1
```

순서대로 명령 식별자(uint32), 보라색 밝기(0–255), 이상 상태(0 또는 1)입니다. 펌웨어는 잘못된 숫자·추가 토큰·96자를 넘은 줄을 거부합니다. 넘친 줄의 끝부분도 명령으로 실행하지 않습니다.

장치 → 브라우저는 부팅 직후, 250ms마다, 명령 접수 직후 다음 JSON 형식 한 줄을 보냅니다.

```json
{"kind":"semiguard-experience","version":2,"seq":7,"uptimeMs":1750,"ledBrightness":180,"commandAck":42,"faultActive":true,"watchdogOff":false}
```

`seq`는 프레임 순서, `commandAck`는 마지막으로 접수한 명령 식별자입니다. `watchdogOff:true`는 대기/통신 중단으로 출력을 꺼 둔 상태입니다. 부팅 때 출력은 OFF이고, 검증된 웹 명령이 와야 점등합니다. 프레임과 명령 식별자는 uint32 범위이며, 브라우저는 중복/역순 프레임을 버리고 순번의 한 바퀴 순환을 처리합니다. 이 규약은 연결 대상의 제품 인증 기능을 제공하지 않습니다. 사용자가 선택한 본 교육용 장치와 함께 사용합니다.

## 검증 범위

소프트웨어 검증은 프레임 해석, 범위/타입 검사, 순번 순환, 전송 제한, 핸드셰이크 전 쓰기 금지, 오래된 상태 폐기와 종료 동작을 대상으로 합니다. 실제 보드 연결, 램프 발광, PWM 극성, 카메라 화질, 전원/발열과 부품 호환성은 아직 검증하지 않았습니다.
