# SemiGuard 기존 사이트의 교육 모듈 체험

기존 사이트의 **실시간 자유 분석 `/live`** 안에 통합했습니다. 기존 훈련·대시보드 메뉴에서 그대로 들어가며, 같은 `EtchLive`를 사용하는 Preview의 `model-preview.html`에서도 동일한 체험이 동작합니다. 새 사이트나 다운로드한 HTML로 이동하지 않습니다. 기존 사이트의 외관·내부 그림·카메라·4항목 그래프·기록을 유지합니다.

## 체험 순서

기본 화면은 챔버·네 가지 현재값과 정상 기준·RF 매칭 조절·미션 상태에 집중합니다. 첫 화면은 내부 구조이며 외형과 모듈 카메라로 전환할 수 있습니다. 추가 RF·유량·배기 조절, 정상 판정의 상세 설명, 그래프·자동 기록, 실물 램프 연결은 각각 펼칠 때 표시됩니다. 긴 판단 근거 입력과 반복 안내는 이 체험 화면에서 제거했습니다. 처음부터 버튼은 현재 체험과 기록을 새로 시작하고, 연결한 장치를 다시 설정하게 만들지는 않습니다.

1. **자유 체험 → 이상 주입**을 누릅니다. 중앙의 보라색 모형 램프와 ③ RF 모의값이 같은 시나리오에 따라 흔들립니다. 흰 보조등 두 개는 계속 켭니다.
2. 주 화면의 **RF 매칭 조절**을 움직이며 빛과 ③ RF 값을 관찰합니다. RF 설정·가스 유량·배기 밸브는 **추가 조절**을 펼쳐 바꿉니다. 현재값·목표값·정상 범위는 챔버 아래 네 칸에 항상 표시됩니다. 수치는 교육용 모의값입니다.
3. **복구 미션 → 미션 시작**에서 90초 안에 네 값의 경보를 해제하고 RF 매칭 안정도를 87% 이상으로 맞춰 5초 유지합니다. 성공하면 **복구 미션 완료!** 대화상자에 점수와 소요 시간이 나옵니다. 닫은 뒤에도 완료 배너에서 결과를 다시 볼 수 있습니다. 초기화나 이상 해제로는 성공 점수를 얻을 수 없습니다. 조작 이력은 체험 경과 시간으로 자동 기록됩니다.
4. **모듈 카메라 → 카메라 설정**에서 PC에 USB로 연결한 모듈 웹캠을 확인하고, **이 장치는 모듈에 장착한 웹캠입니다**에 체크해 등록합니다. 그다음 **모듈 카메라 연결**을 누릅니다. 모듈 웹캠이 없거나 장치 이름이 숨겨져 있으면 연결하지 않으며 내장 카메라로 전환하지 않습니다. 촬영 구도에 맞춰 번호와 값 상자를 옮길 수 있고, 위치는 브라우저의 장치별 설정으로 남습니다.
5. 네 값은 정상일 때 흰 글씨·검정 테두리, 이상일 때 빨간 글씨·검정 테두리로 표시됩니다. 복구 후 정상 범위가 유지되면 흰색으로 돌아옵니다.

| 번호 | 항목 | 단위 | 이번 체험의 모의 정상 범위 |
|---|---|---|---|
| ① | 챔버 압력 | mTorr | 17–23 |
| ② | 가스 유량 | sccm | 90–110 |
| ③ | RF 전력 | W | 440–560 |
| ④ | 챔버 주변 온도 | °C | 31–39 |

범위는 교육용 시나리오를 위해 정한 예시입니다. 실제 식각 장비 사양이나 웨이퍼 온도 기준으로 사용하지 않습니다. 보라색 LED 밝기 역시 실제 RF 전력의 측정이나 교정값이 아닙니다.

조작창과 카메라 화면에서 위 목표값·정상 범위를 바로 확인할 수 있습니다. 경보 후에는 압력 18–22 mTorr, 유량 92–108 sccm, RF 460–540 W, 주변 온도 32–38 °C의 복구 확인 범위에서 0.6초 유지하면 해당 빨간 값이 흰색으로 돌아옵니다. 매칭 안정도는 이번 시뮬레이션의 보조 지표입니다. RF 500 W·유량 100 sccm·배기 50%를 기본값으로 맞춘 뒤, 매칭은 상황마다 달라지는 안정 위치를 찾아 조절합니다. 다섯 초 유지 도중 다시 불안정해지면 유지 시간은 0초부터 시작합니다.

## 실물 연결 준비

웹캠 USB와 모형 제어 보드 USB를 같은 PC에 연결합니다. HTTPS의 독립 창에서 데스크톱 Chrome 또는 Edge로 열고, 카메라와 USB 권한은 각 연결 버튼에서 허용합니다. 카메라 영상은 이 페이지에서 저장·업로드하지 않습니다.

브라우저는 카메라의 물리적 설치 위치를 자동 판별할 수 없으므로 최초 등록은 사용자가 모듈 장착을 확인해야 합니다. 카메라 이름이 숨겨져 있으면 브라우저의 이 사이트 카메라 권한을 허용하고 목록을 새로고침합니다. 이름 확인용으로 기본 카메라를 임시로 켜지 않습니다. 등록 후에는 정확한 장치 ID로 요청하고, 반환된 영상 트랙의 ID도 검사합니다. 등록 웹캠을 빼거나 장치 정보가 바뀌면 중지하며 다른 카메라로 대체하지 않습니다. 등록 정보로 ID와 이름만 해당 브라우저에 보관합니다.

보드, LED, 전원, 드라이버는 아직 선정되지 않았습니다. `firmware/semiguard_experience_uno/semiguard_experience_uno.ino`는 UNO/Nano급 보드의 PWM 핀 9를 사용하는 예제입니다. 선정한 부품의 전압·전류와 드라이버에 맞게 확인한 뒤 업로드해야 합니다. 외부 램프를 GPIO에 직접 연결하지 않습니다. 상세 절차는 `docs/BOOTH_DEVICE_KO.md`에 있습니다.

웹 페이지는 일치하는 v2 펌웨어 응답을 확인한 뒤에만 보라색 램프 명령을 전송합니다. 보드의 ACK는 명령 처리 응답이며 실제 밝기 센서 측정값은 아닙니다. 탭 숨김·페이지 종료·통신 중단 시 명령을 멈추며, 예제 펌웨어는 2초 감시 타이머 후 보라색 출력을 끕니다. 흰 보조등은 별도 상시 점등 회로입니다.

## 개발 및 운영 사이트 반영

기존 `EtchLive.tsx`가 공통 체험 엔진과 v2 USB 연결을 사용합니다. `KiyoEquipmentView`는 보라색 램프의 단계별 밝기와 항목별 경보를 받아 그립니다. 기존 App의 `/live` 인증과 Preview 전용 `model-preview.html` 빌드 정책은 유지합니다. v1 USB 파일은 보존하되 이 화면에서 동시에 마운트하지 않습니다. 실제 반영 대상은 기존 `codex/kiyo-model-live-20261104` 브랜치의 Vercel Preview입니다.

프로젝트 루트에서 실행합니다.

```text
node node_modules/typescript/bin/tsc --noEmit --incremental false --pretty false
node node_modules/vitest/vitest.mjs run --config tests/vitest.booth.config.ts
node node_modules/vite/bin/vite.js build --mode model-preview --outDir ../dist/site-integration
```

Vite의 root가 `client/`이므로 위 확인 빌드의 결과는 프로젝트의 `dist/site-integration/`입니다. 확인 빌드는 기존 전체 앱의 `index.html`과 기존 모형 진입점 `model-preview.html`을 함께 빌드합니다. 배포는 기존 GitHub 브랜치와 Vercel 프로젝트에 반영해야 하며, 새 사이트로 대체하지 않습니다. 앞서 만든 `experience-preview.html`과 단독 HTML은 이전 검토용 참고본입니다.

검증 대상은 전체 사이트 TypeScript·빌드, 기존 경로와 인증 연결, 공통 상태·USB·카메라 수명주기, 모형 밝기와 항목별 경보입니다. 실제 브라우저 화면, 웹캠 권한 및 실물 LED·펌웨어 업로드는 별도로 확인해야 합니다.
