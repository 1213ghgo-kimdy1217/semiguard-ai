## 1. AI 코칭: 재현 가능한 형식 문제와 운영 확인을 분리

현재 Lightning 연결은 일반 텍스트 완성 응답을 사용합니다. 기존 파서는 JSON 객체가 응답 전체의 단일 `json` 코드 블록에 담겨 있어도 바로 `JSON.parse`하여 거절했습니다.

수정은 **앞뒤 설명 없이 응답 전체가 정확히 하나의 JSON 코드 블록인 경우에만 포장을 벗기는 것**입니다. 여러 블록·앞뒤 설명·깨진 JSON은 추출하거나 복구하지 않습니다. 기존 길이 제한, 엄격한 필드 검증, 답안 발췌 일치, 언어·수치·범위 전제·안전 검사는 그대로 실행합니다. 자동 재요청이나 고정 코칭 대체도 추가하지 않았습니다.

모델용 스키마는 정확히 두 항목으로 맞췄습니다. 프롬프트와 기존 후속 검사도 이미 두 항목을 요구하므로, 세 번째 항목이 원래 허용되던 결과를 줄인 것은 아닙니다.

- 회귀 검사: [응답 형식 행동 테스트](../server/coach-completion-format.behavior.test.ts). 올바른 일반 JSON/단일 코드 블록은 성공, 위험 문구·허위 인용·추가 필드·숫자 단정·언어 불일치·세 번째 항목·허위 범위 전제·과대 응답은 거절합니다.
- 기존 `invalid-response` 사례에는 상세 분류가 남아 있지 않아 **그 사례의 원인이 코드 블록이었다고 결론 내리지 않습니다.**
- 사용자가 승인한 최대 두 번의 가상 QA 요청을 기존 공개 사이트에서 실행했습니다. 김대영 계정과 기존 QA ON 분류를 확인했으며 개인정보나 실제 친구 답안은 입력하지 않았습니다.
- 첫 요청은 대기 표시 뒤 코칭 표시와 동의가 초기화되어 결과를 확정하지 못했습니다. 재마운트·통신·모델 중 어느 경계의 문제인지는 확인되지 않았습니다. 두 번째 요청에서는 `nvidia/nemotron-3.5-lightning-30b-a3b`의 코칭 두 항목이 화면에 도착했습니다. 추가 요청은 하지 않았습니다.
- 기존 운영 버전의 성공 한 건은 새 패치의 운영 재검증이나 안정적인 성공률이 아닙니다. 이번 응답에도 범위 초과와 추세 시작을 혼동할 수 있는 표현이 있어 코칭의 사실성 검토는 계속 필요합니다. 원래 그래프·기준 피드백이 판단 근거입니다.
- 허용된 분류 로그 조회는 첫 시도에서 보관 기간 오류, 최근 5분 조회에서는 일치 로그 없음이었습니다. 원문 로그를 추가하거나 비밀값을 내려받지 않았습니다.

## 2. 사용하지 않는 템플릿 정리

`server/_core/dataApi.ts`와 `voiceTranscription.ts`의 파일명·내보낸 함수·타입을 전체 저장소에서 대소문자 구분 없이 찾아 외부 사용처가 없음을 확인하고 두 파일(348줄)만 제거했습니다. 실제 라우터·빌드 진입점의 연결도 없었습니다. 기존 AI 어댑터가 사용하는 Manus 설정, 의존성과 잠금 파일은 그대로 뒀습니다.

## 3. 실제 로직을 연결한 행동 테스트

[계정 연습 흐름 테스트](../server/training-account-flow.behavior.test.ts)는 실제 라우터·저장 모듈·직렬화·규칙 기준·공유 JWT를 연결하고 DB 경계만 메모리로 대체합니다.

- 8개 공정 각각에서 중간 저장 → 같은 계정의 독립 요청에서 복원 → 관찰 미완료 제출 차단 → 완료 제출 → 동일 제출 키로 재요청해 중복 방지 → 다른 계정 격리.
- 공유 생성의 소유자·별도 동의 확인 → 비로그인 수신자의 선택 답안 열람 → 개인정보·서술형 제외 → 정확히 7일이 되는 시점에 만료.
- 외부 요청이 없음을 확인합니다. 이는 실제 HTTP 인증, MySQL, 물리적 기기 간 동기화나 화면 전체 재시작 검증이 아닙니다.

## 남은 일: 실제 사용자와 운영 경계

1. 학교 친구 외의 다른 학년 학생·지도교사에게 **설명 없이 공정 하나 선택 → 관찰 → 판단 제출 → 복기** 과제만 줍니다. 도움 요청 전 첫 클릭, 막힌 단계, 완료 여부와 이유를 기록합니다. 참여자 A/B처럼 익명 표기로 남기고, 통계 동의 거절도 정상 이용으로 취급합니다.
2. 방문·시작·완료·재방문의 분모, 기간, QA 제외 여부, 자동/수동 근거를 따로 남깁니다. 기존 자기보고 22명이나 재방문 자료를 새 자동 측정 실적으로 바꾸지 않습니다.
3. GA의 테스트 필터 상태를 확인한 뒤 변경 여부를 별도 승인받습니다. 활성 제외는 미래 데이터에 영향을 주므로 이 작업에서 임의 변경하지 않았습니다.
4. 새 패치 공개 반영 승인을 받은 뒤 승인 계정·가상 답안으로 AI 응답과 실패 안내를 다시 검사합니다. 첫 요청 표시 초기화의 재현, 응답 내용의 추세/범위 구분도 확인합니다. 실제 키·답안 본문은 로그에 남기지 않습니다.
5. 승인된 계정으로 두 실제 기기에서 중간 저장·이어하기를 확인하고, 별도 수신자 환경에서 공유 링크를 열어 봅니다. 현재의 모의 저장소 테스트를 그 증거로 대신하지 않습니다.
