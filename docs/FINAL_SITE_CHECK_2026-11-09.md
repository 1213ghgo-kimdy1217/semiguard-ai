# SemiGuard 최종 점검 · 2026-11-09

공유 링크에서 로그인하면 같은 기록으로 돌아옵니다. AI 코칭은 전체 가상 기록에서 신호의 변화 패턴을 읽고, 일부 명백한 기록 모순을 걸러냅니다. GitHub 소개와 검사를 현재 학습 흐름에 맞췄습니다.

## AI 코칭 재현과 수정

1. 웨이퍼 판단 연습의 가상 답안으로 코칭을 요청한 상황을 만들고, 모델이 두께 검사 지수가 정상 참고 범위를 벗어났다고 단정한 응답을 재현했습니다. 실제 가상 기록에서는 두께 지수가 해당 범위 안에 있었지만 이전 검사는 이 문장을 통과시켰습니다.
2. 서버가 전체 가상 기록을 읽어 범위 내 유지, 복귀, 반복 이탈, 종료 시 이탈과 방향을 계산해 코칭에 제공합니다. 예를 들어 포토의 일시적인 변화와 금속배선의 반복 변화를 구분합니다. 명백한 이탈·복귀 단정과 이탈을 전제한 구간 질문을 검사하며, 조건형 질문과 학습자 원문 인용은 유지합니다.
3. 코칭 요청 중 로그인이 만료되면 같은 복기 화면에서 다시 로그인할 방법을 안내합니다. 새 답안을 보낼 때는 기존처럼 학습자가 직접 동의하고 요청합니다.
4. [범위 전제 검사](../server/coach-range-premise.test.ts)와 [코칭 요청·응답 검사](../server/judgment-coach.test.ts)는 가상 응답으로 재현합니다. 모델 가중치, 계정 데이터, 채점 기준은 변경하지 않았습니다. 공급자 응답과 실제 코칭 문장의 품질은 운영 검증에서 따로 확인합니다.

## 계정 흐름과 저장

- [계정 흐름 테스트](../server/training-account-flow.behavior.test.ts)는 8개 공정 중간 저장을 다른 인증 요청에서 복원하고, 소유자 분리와 공유 만료를 확인합니다. 저장소는 테스트용입니다.
- [공유 수신 테스트](../server/shared-training-return.behavior.test.ts)는 로그인 후 같은 탭에서 원래 기록으로 돌아가기, 만료된 이동 정보 처리, 공유 열람의 로그인 요구를 확인합니다. 새 클라이언트는 공유 토큰을 조회 본문에 보냅니다. 배포 전에 열린 이전 클라이언트의 조회 방식도 계속 처리합니다.
- 검증 시에는 다른 브라우저나 기기에서 같은 테스트 계정으로 중간 저장을 열고, 별도 수신 계정에서 공유 링크 → 로그인 → 동일한 기록을 확인합니다. 물리적 기기와 운영 DB 검증 결과는 모의 검사와 따로 기록합니다.

## 참가자 관찰과 집계

- 다른 학년 학생이나 실습 지도교사에게 “공정 하나를 골라 관찰을 시작하고, 판단을 제출한 뒤 근거를 다시 확인해 주세요”라는 과제만 안내합니다. 첫 클릭, 막힌 단계, 도움 여부와 완료 여부를 익명으로 적습니다.
- `참가자 코드 / 학년 또는 역할 / 첫 클릭 / 막힌 단계 / 도움 여부 / 완료 여부 / 관찰 메모` 형식으로 기록합니다. 이름, 계정 정보와 답안 원문은 이 기록에 넣지 않습니다.
- [사이트 집계](practice-measurement.md)와 [GA 수신](google-analytics.md)은 따로 확인합니다. 팀·테스트 모드는 참가자 지표에서 구분합니다. 보고할 때 기간, 분모, QA 제외 기준을 함께 남깁니다. 과거 QA 수신을 실제 참가자 성과로 계산하지 않습니다.

## 검사 범위

운영에 연결된 소스에서 출발해 타입 검사, 전체 자동 테스트 405개 파일·2,412개, 배포용 빌드와 로컬 API 상태 검사를 통과했습니다. 전체 테스트와 QA에는 가상 데이터를 사용했습니다. 실제 참가자 관찰, GA 필터의 현재 상태, 운영 NVIDIA 응답은 별도 확인이 필요한 항목입니다.

빌드된 화면에서는 가상 계정으로 공유 링크 → 로그인 → 같은 기록 열람을 확인했습니다. 서로 다른 데스크톱·모바일 브라우저 환경에서 중간 저장을 24초에 저장하고 이어 열었습니다. 가상 코칭 응답으로 세 언어의 결과 카드와 세션 만료 시 같은 복기 화면에 머무르는 동작도 확인했습니다.
