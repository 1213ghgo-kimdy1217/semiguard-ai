# SemiGuard 2.0 — 현재 제품 기준

기준일: 2026-09-19. 「SemiGuard AI」의 최신 확정 방향을 반영한 PRD / IA 기준.

## 제품 구조

반도체 장비 데이터를 실시간으로 관찰하고, 이상 상황의 판단 과정을 반복 연습하는 시뮬레이션 플랫폼. 강의·수료 과정이나 반도체 백과사전을 제품의 중심으로 만들지 않는다.

1. **Live Equipment Simulation**: 같은 가상 식각 챔버의 단계·센서 엔진으로 자유 관찰. 기존 대시보드와 아직 동일한 기능이 아니다.
2. **Scenario Training**: 브리핑 → 관찰 ↔ 판단 기록 → 제출. Scenario 01부터 완성한다.
3. **AI Judgment Coach**: 사용자의 사실·추정 구분과 근거 서술을 돕는다. 실제 연결 전에는 규칙 피드백만 표시한다.
4. **Timeline Review**: 기준 변화·사용자가 표시한 시점·답안의 시작 시점을 비교한다.
5. **Personal Skill Profile**: 사용자 소유의 실제 훈련 기록에만 근거한다. 기록이 부족하면 부족하다고 표시한다.

Learning Hub는 위 다섯 기능을 돕는 선택적 준비 안내다. 이미 아는 사용자는 바로 훈련할 수 있어야 한다.

## IA와 실제 구현 상태

| 영역 | 현재 | 다음 구현 |
| --- | --- | --- |
| 훈련 홈 /training | Scenario 01 및 기존 자유 분석 진입 | 시뮬레이션 중심 진입 구조 |
| Scenario 01 | 1초 관찰·시점 표시·근거 비교·규칙 평가 | 학습 목표별 검증과 시도 저장 |
| 자유 관찰 /live | 식각 엔진의 독립 180초 재생, 과거 비교, 복수 메모, JSON 내보내기 (로컬 검증) | 패턴 다양화 및 계정별 기록 |
| 기존 데모 /dashboard | 기존 4센서 데모, 로그인 필요, 보존 | 신규 관찰 화면으로 점진적 전환 |
| 타임라인 복기 | 제출 후 그래프·수치 비교 | 표시 행위의 이력과 선택 시점 분리 |
| AI 코치 | 미연결, 사전 작성 도움말만 제공 | 서버 연결·오류 대체·비공개 정보 보호 |
| 개인 기록 | 현재 탭 임시 저장 | 인증 사용자별 저장·조회·접근 차단 테스트 |
| 준비 안내 | 훈련에 필요한 읽는 법, 건너뛰기 가능 | 출처 검토된 장비·센서 개념만 확장 |

과거 시점으로 옮길 수 있는 marker를 실제 발견 시각이나 반응 속도 지표로 사용하지 않는다. 그런 지표를 도입하려면 실제 기록 버튼을 누른 경과 시간과 표시 대상 시간을 별도 저장하고 수정 이력을 남겨야 한다.

강제적인 ‘시나리오 통과 후 대시보드 잠금 해제’ 구조를 사용하지 않는다. 복기 후 자유 분석으로 넘어가는 추천 경로는 제공한다.

## 첫 구현 범위

- 가상 플라즈마 식각 챔버 Scenario 01.
- 단계별 가상 기준과 재현 가능한 신호. 물리 운전값 대신 명시된 상대지수.
- 180초 교육용 재생, 1초 갱신, 일시정지, 탭 이탈 시 정지.
- 지금까지의 관측만 표시. 전체 해설은 제출 후 공개.
- 변화 발견 시점과 사용자가 추정한 변화 시작 시점의 구분.
- 구조화 선택 항목의 규칙 기반 피드백. 서술형 의미는 자동 평가하지 않음.
- 현재 탭의 버전별 임시 복구. 계정 저장·기기 간 동기화가 아님.
- 자유 분석으로 독립 진입 및 훈련으로 돌아오기.

기존 /dashboard의 전류·온도·진동·소음은 식각 시나리오와 다른 가상 데이터다. 새 /live는 같은 식각 엔진의 독립 실행이며 매번 같은 패턴이다. 두 화면을 같은 장비의 연속 실행처럼 표현하지 않는다. 기존 인증과 로그를 보존하고 자동수집/AI 분석을 새 시나리오에 연결하지 않는다. /live 메모는 화면 내 임시 상태이며 이동 전 파일 내보내기가 필요하다. 아직 계정 저장이나 새 패턴은 제공하지 않는다.

## 후속 구현 순서

1. 실제 화면의 사용자 흐름 검증과 미리보기 검토.
2. 인증 사용자별 훈련 시도 저장·조회·복기. API 소유권 검증과 기존 데이터 보존 필수.
3. NVIDIA 코치: 실제 연결 확인 후 서버 전용 키로 연결. 위험 점수·통계·정답을 생성 모델에 맡기지 않는다.
4. 같은 식각 엔진을 쓰는 자유 관찰 모드. 훈련 답안·진행 상태와 분리하고 기존 대시보드를 보존한다.
5. 추가 시나리오와 기록 기반 프로필. Learning Hub는 훈련에 필요한 만큼만 확장한다.

위 구현 순서는 선행 의존성을 고려한 작업 순서이며, 제품의 중심은 실시간 판단 훈련이다. AI와 기록이 연결되기 전에는 가짜 점수·성장률·개인 분석을 만들지 않는다.

## OGQ 적용 경계

OGQ는 보조 시각 자산 후보이며 핵심 훈련보다 우선하지 않는다. 채팅에 공유된 키를 재사용하지 않는다. 문서와 대회 사용 범위, 저장·재배포 조건을 확인하고 새 서버 전용 키를 확보하기 전까지 연동하지 않는다. 코드·브라우저·로그에 비밀키를 넣지 않는다.

음성·교관 화면·시나리오 제작기는 이후 단계다. 미구현 기능을 활성 버튼이나 가짜 성과 수치로 표현하지 않는다. 기업 채용·인사 판정이나 실제 장비 제어를 위한 시스템이 아니다.

## 검증 및 배포

TypeScript → 전체 Vitest → production build. 배포는 기존 Vercel 프로젝트에서 수행하고 별도 Sites 프로젝트를 만들지 않는다. 검증과 승인 없이 main 병합하지 않는다.
